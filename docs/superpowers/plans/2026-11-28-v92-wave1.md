# v9.2 Leftovers Wave 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build P88 (Dial a number checks), P34 (Excel "Skip or update") and P19 (Archived & blocked on one tab) into the pages that already exist.

**Architecture:** P88 adds one read-only backend check (`GET /api/v1/calls/dial-check`) built from the same rules the Call button enforces, plus a `today` filter on `/calls/recent`; the frontend shows them in the Manual Dial tab (right pane on xl, under the pad below xl). P34 lets an "exists" row carry `action: "update"` through `template_bulk` and the bulk submit route, which reuses the template edit logic. P19 is frontend only: the Blocked tab folds into Archived.

**Tech Stack:** FastAPI + Supabase (backend, pytest), Next.js 14 + TypeScript + Tailwind (frontend, vitest, next lint).

**Spec:** `docs/superpowers/specs/2026-11-28-v92-wave1-design.md`

## Global Constraints

- No new page, route segment or tab in the frontend. (Spec: "No new page, route or tab for any of the three.")
- National DND is never shown as OK: its state is always `not_checked`, label "National DND list", detail "Not checked".
- The dial screen must agree with the Call button: both use `find_lead_for_dial` and `pre_dial_block`.
- Hidden numbers stay hidden: any phone in a dial-check or recent response goes through `phone_mask_for`.
- Customer-facing copy says "Anril", never "Aira"; plain words, no "API", "webhook", "segment".
- Backend tests: `cd backend && PYTHONUTF8=1 python -m pytest` (never bare `pytest`). Frontend: `npm run typecheck`, `npm run lint`, `npm test` in `frontend/`.
- Nothing is committed without Keerthi's explicit OK (memory rule): the "Commit" step of every task is replaced by "leave uncommitted, list the files".

## Review Focus

1. A number typed without +91 (e.g. `98431 20123`) for a customer stored as `+919843120123` who is on Said stop: dial-check shows it blocked AND `/calls/initiate` refuses. (Task 1 tests.)
2. A telecaller whose business hides numbers: dial-check's customer `phone` is masked and Dialled today shows masked numbers. (Task 1, Task 3 tests.)
3. An Excel row set to Update whose existing template is PENDING: the row comes back `refused` with a plain reason, nothing changes on Meta. (Task 5 test.)
4. An Excel Update row whose Type differs from the existing template: it updates, and the result says the type stays. (Task 5 test.)
5. Unblocking from the expanded Blocked list on the merged tab removes the row and lowers the count without reloading the archived table. (Task 7 browser check.)

Check rows, in this order, with this exact copy:
| key | label | states |
|---|---|---|
| `said_stop` | "Not on Said stop" | ok / blocked (detail "On Said stop") |

| `dnd` | "National DND list" | always not_checked, detail "Not checked" |
| `hours` | f"Calling hours {clock_words(start)} – {clock_words(end)}" | only when `calling_hours_on`; ok (detail now as "4:10 PM") / outside: blocked for role `caller`, warn for others (detail "Outside hours") |
| `daily_limit` | "Daily call limit" | only for role `caller` with `daily_limit_on`; ok / blocked (detail "Reached") |
| `called_today` | f"Called {n} time(s) today already" | only when n ≥ 1; warn, detail f"Last: {time}" |

`blocked_reason` is the first blocked row's message, using the same words `initiate_call` raises ("This customer is on Said stop, so they can't be called", "Lead is on Do Not Call", `hours_message(rules)`, "Daily call limit reached").
